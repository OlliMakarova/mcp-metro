# Цель

Создать универсальный MCP-инструмент, который возвращает либо сведения о станции метро, либо сведения
о кратчайших маршрутах между двумя станциями.

# Инструкции

Универсальный инструмент называется `mos_metro_info`.

Входные параметры:

- `first_metro_station` — название станции отправления или станции, о которой мы хотим получить информацию.
  В обработчике инструмента должен осуществляться неточный поиск подходящей станции по переданному значению.
  Оно может быть передано на любом из четырёх языков, с ошибками или опечатками. Если по переданному значению
  найдена ровно одна станция — она используется. Если найдено несколько вариантов, ответом инструмента должна
  быть просьба выбрать подходящую станцию из найденных вариантов. Если не найдено ни одной станции — ответ
  пользователю: просьба уточнить название станции.
- `second_metro_station` — название станции прибытия.
  В обработчике инструмента должен осуществляться неточный поиск аналогично `first_metro_station`.
  Важно: если переданы обе станции и обе требуют уточнения, то запрашивать уточнение у пользователя сразу
  по двум станциям. Значит, в ответе инструмента с просьбой уточнения должно быть два списка станций для выбора.
- `action` — тип действия, энумератор с двумя значениями: `search_route` — поиск маршрута,
  `get_station_info` — получение информации о станции.

В случае `search_route` в обработчике проверять обязательность указания обеих станций.
Возвращать исчерпывающую информацию о маршрутах, от 1 до 4 штук:

- полное время в пути с учётом времени ожидания на станциях;
- станции;
- пересадки;
- время на перегонах между пересадками;
- в какие вагоны входить для удобной пересадки;
- сведения о маршрутах наземного транспорта на конечных станциях;
- сведения о том, является ли линия МЦД;
- сведения о ремонтах эскалаторов, входов, лифтов;
- и прочие сведения, которые предоставляет mosmetro.ru.

В случае `get_station_info` параметр `second_metro_station` не обязателен.
Возвращать исчерпывающую информацию о станции.

Важно: все ответы инструмента оформлять в markdown. Структуру передавать списками и таблицами.

# Задача

- Удалить шаблонные и тестовые инструменты, ресурсы, эндпоинты.
- Создать новый инструмент.
- Сделать REST-эндпоинты:
  - неточный поиск станции по её наименованию;
  - получение сведений о станции;
  - получение маршрутов, до 4 штук, с сопутствующими сведениями.

  Обязательно предусмотреть rate limiting (ограничение частоты запросов).
- Сформулировать AGENT_BRIEF в `src/prompts/agent-brief.ts` и AGENT_PROMPT в `src/prompts/agent-prompt.ts`.
- Вместо тестовых примеров в `tests/mcp/test-cases.js` написать тесты для нашего случая.
- Обновить README.md, чтобы отразить новый проект. Этот README.md будет использоваться при поиске этого MCP
  в системе RAG, поэтому описать суть инструмента, его возможности, способы установки, список инструментов,
  ресурсов, подсказок. Кратко и по делу.
