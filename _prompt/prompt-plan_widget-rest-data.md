# Промпт-план: доработка mcp-metro — данные виджета по REST (самоописывающая ссылка)

> **Исполнителю.** Это план-промпт. Отмечай каждый пункт чек-листа `- [x]` в этом же файле сразу после того,
> как пункт реально выполнен и проверен. Последний этап — обновление документации — обязателен.

## Цель (целевое состояние)

mcp-metro — обособленный спек-совместимый сервер MCP Apps. Виджет маршрутов состоит из кешируемой UI-части
(версионированный ресурс `ui://mos-metro/routes.<hash>.html`) и динамических данных, которые виджет
загружает сам по REST. Ссылка на данные — **самоописывающая**: она содержит параметры построения маршрута
(станции, язык, момент времени), а сервер строит данные заново при каждом обращении. Ссылка вечная —
никакого кеша выданных данных, TTL и потери ссылок при рестарте сервера не существует. Благодаря этому:

- контекст LLM не раздувается: модель видит маркдаун и ~40 токенов служебной ссылки;
- виджет, полученный сколь угодно давно, открывается и показывает маршрут, построенный на записанный в
  ссылке момент времени; кнопка «Обновить маршрут» строит его же на «сейчас»;
- виджет одинаково работает в Claude Desktop, Agent Tester и в универсальном хосте mem-bot
  (webchat / админка / Telegram Mini App) — все различия лежат на стороне хостов; кнопка обновления
  работает во всех каналах, включая Telegram, потому что это обычный `fetch`, а не `tools/call`;
- mcp-metro ничего не знает про конкретные хосты.

## Контракт

Ответ `mos_metro_info` (action=search_route, хост с поддержкой MCP Apps):

```json
{
  "content": [{ "type": "text", "text": "<маркдаун, как сейчас>" }],
  "structuredContent": {
    "widget": "metro-routes",
    "dataUrl": "https://<publicBaseUrl>/widget-data?from=<ids>&to=<ids>&lang=ru&at=<ISO>&sig=<hmac>"
  }
}
```

Параметры ссылки:

- `from`, `to` — id станций (платформ кластера) отправления и назначения через запятую — ровно те
  `option.ids`, которыми инструмент вызывал `findBestRoutes`;
- `lang` — язык ответа (`en|ru|ar|cn`);
- `at` — момент построения маршрута, ISO с таймзоной; запрос БЕЗ `at` означает «сейчас» — это штатный
  путь кнопки «Обновить маршрут»;
- `sig` — HMAC-подпись параметров `from|to|lang` серверным секретом. Подпись НЕ покрывает `at` — поэтому
  виджет может убрать/заменить момент времени, не ломая подпись. Назначение подписи: конечная точка
  обслуживает только ссылки, выданные инструментом, и не превращается в публичный API построения
  маршрутов (Yen-поиск — недешёвая операция).

`GET /widget-data?...` → `200` + JSON `IRoutesWidgetData` (текущий формат payload, построенный на момент
`at` или «сейчас»); `400` при кривых параметрах/подписи; `404` если станции не найдены в актуальном
датасете (данные метро обновились). CORS: `Access-Control-Allow-Origin: *` (песочницы шлют `Origin: null`).

Хосты без поддержки MCP Apps получают, как и сейчас, только текст — ни ссылки, ни `structuredContent`.
Маркдаун для модели остаётся полным (весь текст маршрутов) — это единственный источник информации для
модели и для хостов без поддержки виджетов; сокращать его не планируется.

## Этап 1. Конфигурация

- [ ] Параметр `webServer.publicBaseUrl` в `config/default.yaml` (по умолчанию пусто) + маппинг env в
      `custom-environment-variables.yaml` + расширение типа в `src/_types_/custom-config.ts`.
      Пустое значение → `http://localhost:<webServer.port>` (локальная разработка и Agent Tester работают
      без настройки).
- [ ] `publicBaseUrl` — единственный источник внешнего адреса: от него строятся и `dataUrl`, и
      `connectDomains` в CSP ресурса. Никаких построений адреса из заголовков запроса и дополнительных
      списков origin'ов не существует.
- [ ] Секрет подписи `widgetData.signSecret`: задаётся в конфиге; пустое значение → генерируется при
      старте случайно (после рестарта старые подписи невалидны — для локальной разработки приемлемо,
      в проде секрет задан и ссылки вечны).

## Этап 2. Модуль ссылки данных

- [ ] Модуль `src/tools/metro/widget-data-link.ts`: `buildWidgetDataUrl({ fromIds, toIds, lang, at })` —
      сборка URL с подписью; `parseWidgetDataQuery(query)` — разбор и проверка подписи
      (`timingSafeEqual`), возврат типизированных параметров либо понятной ошибки. Подпись —
      HMAC-SHA256 от канонической строки `from|to|lang`, усечённая до разумной длины (например, 32
      hex-символа).

## Этап 3. REST-маршрут

- [ ] `GET /widget-data` в `src/api/router.ts` (tsoa): разбор параметров → `findBestRoutes(dataset,
      fromIds, toIds, { k: ROUTE_COUNT, at })` (при отсутствии `at` — текущий момент) →
      `buildRoutesWidgetData(...)` → JSON. Имена «откуда»/«куда» восстанавливаются из датасета по id
      (имя станции кластера на языке `lang`).
- [ ] Ошибки: `400` — кривые параметры или подпись; `404` — станции отсутствуют в актуальном датасете;
      `503` — данные метро временно недоступны. Тексты ошибок — англоязычные, без имён источников
      (`hideSourceNames`).
- [ ] Заголовки CORS `*` (включая ответ на preflight `OPTIONS`, если tsoa/фреймворк не делает это сам).
- [ ] Ограничение частоты запросов через `rate-limiter-flexible` (уже в зависимостях): 60 запросов в минуту
      с одного IP; легитимные повторные открытия виджета в лимит укладываются с большим запасом.
- [ ] Мемоизация вычислений: готовый ответ кладётся в маленький LRU-кеш (~200 записей, время жизни
      несколько минут). Ключ — `from|to|lang|effectiveAt-до-минуты|версия датасета`, где `effectiveAt` =
      `at` из ссылки, а при его отсутствии (запрос кнопки «Обновить») — текущий момент; версия датасета —
      отметки загрузки схемы/уведомлений, чтобы обновление данных метро естественно инвалидировало кеш.
      Повторные и переборные запросы бьют в кеш, а не в поиск маршрутов. Это кеш вычислений для защиты
      процессора, а не кеш выданных ссылок: ссылки остаются вечными, поведение виджета не меняется.
      Значения `at` из будущего не ограничиваются.

## Этап 4. Инструмент

- [ ] `handleMosMetroInfo` (ветка «хост поддерживает MCP Apps»): `structuredContent` =
      `{ widget: 'metro-routes', dataUrl }`, где `dataUrl` собран из `option.ids` обеих станций, `lang`
      и момента вызова. Полного payload в ответе инструмента не существует.

## Этап 5. Ресурс виджета: версионированный URI и CSP

- [ ] Версионированный URI ресурса: адрес включает хеш содержимого HTML —
      `ui://mos-metro/routes.<hash>.html`, где хеш вычисляется при старте сервера из файла виджета
      (короткий, например первые 8 символов sha256). Тот же адрес — в `_meta.ui.resourceUri` инструмента
      и в регистрации ресурса. Хосты, кеширующие HTML по URI бессрочно (универсальный хост mem-bot),
      перечитывают его только при реальном изменении виджета.
- [ ] `src/tools/metro/widget-resource.ts`: `_meta.ui.csp.connectDomains = [<origin publicBaseUrl>]` —
      чтобы спек-хосты (Claude Desktop) разрешили iframe единственный сетевой запрос. Формат ключа сверить
      с `FA-MCP-SDK-DOC/10-mcp-apps.md` §5.4 (`connectDomains`) и `IUiResourceMeta` (`csp` как запись
      «директива → источники») — выбрать поддерживаемую SDK форму.

## Этап 6. Виджет (`src/tools/metro/routes-widget.html`)

- [ ] `onToolResult`: `structuredContent.dataUrl` → состояние «Загружаем маршруты…» → `fetch(dataUrl)` →
      рендер текущей разметки. Ветки с полным payload в `structuredContent` не существует.
- [ ] Кнопка «Обновить маршрут»: тот же `dataUrl`, из которого удалён параметр `at` (подпись остаётся
      валидной — она `at` не покрывает) → маршрут строится на «сейчас». Работает во всех каналах,
      включая Telegram Mini App: это обычный `fetch`, `tools/call` не используется. Подпись кнопки —
      во всех 4 языках i18n-словаря.
- [ ] Ошибки: сеть недоступна/запрещена CSP → понятное сообщение; `400/404` → «Не удалось загрузить
      данные маршрута — задайте вопрос заново» (все 4 языка). Фолбэка со встраиванием полного payload
      не существует: такой хост покажет сообщение об ошибке, пользователь прочитает текстовый ответ;
      ограничение фиксируется в README (Этап 8).
- [ ] Повторное открытие iframe (пересоздание хостом) повторно запрашивает тот же `dataUrl` — работает
      всегда, ссылка вечная.

## Этап 7. Тесты и проверка

- [ ] Юнит модуля ссылки: сборка/разбор, отклонение битой подписи, `at` вне подписи (удаление `at` не
      ломает подпись).
- [ ] Тест REST: `200` с корректным JSON и CORS-заголовками (с `at` и без); `400` по битой подписи;
      `404` по несуществующим id станций.
- [ ] `tests/mcp/test-cases.js`: ответ search_route при заявленной поддержке Apps содержит `dataUrl` и не
      содержит `variants`; по `dataUrl` доступен JSON с `variants`.
- [ ] Полный прогон: `yarn cb`, `yarn lint`, `yarn typecheck`, `yarn format`, тесты STDIO/HTTP/SSE.
- [ ] Сквозная проверка через Agent Tester (headless, `appMode: true`): в `app_calls` — `uiResource` и
      короткий `structuredContent`; визуальная проверка виджета (загрузка данных по REST из песочницы,
      работа кнопки «Обновить маршрут»).

## Критерии приёмки

- [ ] `yarn cb`, `yarn lint`, `yarn typecheck`, `yarn format` — без ошибок; тесты `yarn test:mcp`,
      `yarn test:mcp-http`, `yarn test:mcp-sse` — зелёные (HTTP/SSE требуют запущенного `yarn start`).
- [ ] Прямой MCP-клиент с заявленным расширением `io.modelcontextprotocol/ui`: ответ search_route содержит
      `structuredContent = { widget: 'metro-routes', dataUrl }` без `variants`; `GET dataUrl` → JSON с
      `variants`; тот же запрос без `at` → маршрут «на сейчас». Клиент без расширения получает только текст.
- [ ] Битая подпись → `400`; несуществующие id станций → `404`; CORS-заголовки присутствуют.
- [ ] Agent Tester (сначала `yarn check-llm`): headless `POST /agent-tester/api/chat/test` с
      `appMode: true` и `mcpConfig` — в `trace.turns[].app_calls` есть `uiResource`
      (`ui://mos-metro/routes.<hash>.html`) и короткий `structuredContent`. На Windows кириллицу в теле
      слать через `--data-binary @file` (UTF-8), иначе текст исказится (см. `08-…md`, «Windows Encoding
      Note»).
- [ ] Визуально (страница-хост из test-log или Agent Tester с включённым Apps): виджет показывает
      состояние загрузки, затем маршруты; кнопка «Обновить маршрут» перестраивает на «сейчас»;
      при недоступном сервере данных — понятное сообщение об ошибке.
