# Источники данных о Петербургском метрополитене

**Цель:** собрать данные для MCP-сервера, который ищет станции, строит маршруты, рассчитывает время поездки с пересадками и учитывает режим работы метро.

**Дата проверки источников:** 26 июля 2026 года.

> Документ относится только к Санкт-Петербургу. Источники по Московскому метро намеренно исключены.

---

## 1. Краткий вывод

Для первой рабочей версии лучше использовать несколько источников одновременно:

1. **Официальный сайт Петербургского метрополитена** — режим работы станций, первые и последние поезда, интервалы, временные закрытия, ремонты, схема, переходы и доступность.
2. **GTFS Петербургского метрополитена** — потенциально лучший машинно-читаемый источник станций, линий, последовательностей остановок и времени поездов, но исходный сервер нестабилен.
3. **OpenStreetMap** — стабильный резерв для координат, топологии линий, входов, выходов и пересадочных объектов.
4. **Яндекс Метро** — проверка маршрутов, продолжительности поездки, пересадок и актуальных закрытий; внутренние методы недокументированы.
5. **DaData** — нормализация названий, линий, координат и признака закрытия станции.
6. **Transitland** — реестр и архив зарегистрированного GTFS-фида.
7. **2ГИС и другие маршрутизаторы** — только для контрольного сравнения результатов, а не как основная база.

Для матрицы времени между всеми станциями не нужно запрашивать каждый маршрут у внешнего сервиса. Следует построить локальный взвешенный граф:

- вершины — станции на конкретных линиях;
- рёбра `ride` — поездка между соседними станциями;
- рёбра `transfer` — переходы между платформами/линиями;
- веса — длительность перегона или перехода.

Затем матрица рассчитывается локально алгоритмом Дейкстры от каждой станции.

## 2.2. Режим работы станций, вестибюлей, первые и последние поезда

Основная страница:

- https://metro.spb.ru/rejimrabotystancii.html

На странице публикуются:

- время открытия каждого вестибюля;
- время закрытия на вход;
- время закрытия на выход;
- время прохождения первых поездов;
- время прохождения последних поездов;
- направления движения;

На момент проверки официальный сайт указывает, что переход между линиями заканчивается в **00:15**. Актуальная таблица режима работы действует с указанной на странице даты и может заменяться новой версией.

### Как обновлять

Не следует жёстко привязываться к имени датированной страницы. Надёжнее:

1. загружать `rejimrabotystancii.html`;
2. извлекать текущую таблицу и дату действия;
3. сохранять исходный HTML;
4. рассчитывать SHA-256;
5. при изменении проводить повторный импорт и проверку.

## 2.3. Интервалы движения поездов

Текущая страница режима работы содержит ссылку на актуальную таблицу интервалов. Датированные страницы имеют вид:

```text
https://metro.spb.ru/intervalpoezdDDMMYYYY.html
```

Пример найденной официальной страницы:

- https://metro.spb.ru/intervalpoezd01062026.html

Страница от 1 июня 2026 года содержит графики транспортного обслуживания, действовавшие с 01.06.2026 по 30.06.2026.

Также публикуются отдельные графики для специальных ночей и массовых мероприятий, например:

- https://metro.spb.ru/intervalpoezd27062026.html

Данные обычно разделены по:

- линии/маршруту;
- участку линии, если применяется зонное движение;
- времени суток;
- рабочим дням;
- субботам;
- воскресеньям;
- минимальному и максимальному интервалу.

### Правильный способ находить актуальную таблицу

Не угадывать дату URL, а каждый раз:

1. открыть `https://metro.spb.ru/rejimrabotystancii.html`;
2. найти ссылку, текст которой содержит «Интервалы движения поездов»;
3. перейти по найденному `href`;
4. сохранить HTML и дату действия;
5. распарсить таблицы.

### Пример загрузчика

```python
from __future__ import annotations

from io import StringIO
from urllib.parse import urljoin

import pandas as pd
import requests
from bs4 import BeautifulSoup

BASE_URL = "https://metro.spb.ru/"
INDEX_URL = urljoin(BASE_URL, "rejimrabotystancii.html")


def get_html(url: str) -> str:
    response = requests.get(
        url,
        headers={
            "User-Agent": "MetroMCP/1.0 (+contact@example.com)",
            "Accept-Language": "ru-RU,ru;q=0.9",
        },
        timeout=45,
    )
    response.raise_for_status()
    return response.text


def find_current_interval_url() -> str:
    soup = BeautifulSoup(get_html(INDEX_URL), "html.parser")

    for link in soup.find_all("a", href=True):
        text = " ".join(link.get_text(" ", strip=True).split()).lower()
        if "интервал" in text and "движен" in text:
            return urljoin(BASE_URL, link["href"])

    raise RuntimeError("Ссылка на интервалы не найдена")


def load_interval_tables(url: str) -> list[pd.DataFrame]:
    html = get_html(url)
    return pd.read_html(StringIO(html))


url = find_current_interval_url()
tables = load_interval_tables(url)
print(url, len(tables))
```

# 3. GTFS Петербургского метрополитена

Зарегистрированный адрес статического GTFS:

- http://transport.orgp.spb.ru/Portal/transport/internalapi/gtfs/feed.zip

Карточка фида в Transitland:

- https://www.transit.land/feeds/f-udt-%D0%BF%D0%B5%D1%82%D0%B5%D1%80%D0%B1%D1%83%D1%80%D0%B3%D1%81%D0%BA%D0%B8%D0%B9~%D0%BC%D0%B5%D1%82%D1%80%D0%BE%D0%BF%D0%BE%D0%BB%D0%B8%D1%82%D0%B5%D0%BD

Transitland связывает этот фид с оператором «Петербургский метрополитен». Однако на момент проверки он сообщает:

- время последней успешной загрузки неизвестно;
- исходный адрес отвечает нестабильно;
- зафиксирована ошибка `i/o timeout`;
- в архиве Transitland может быть доступна историческая версия.

## 3.1. Что потенциально содержится в GTFS

Ожидаемые файлы:

```text
agency.txt
routes.txt
stops.txt
trips.txt
stop_times.txt
calendar.txt
calendar_dates.txt
transfers.txt        # может отсутствовать
shapes.txt           # может отсутствовать
feed_info.txt        # в последней известной версии отсутствовал
```

Наиболее полезные данные:

- `routes.txt` — линии;
- `stops.txt` — станции и координаты;
- `trips.txt` — направления и рейсы;
- `stop_times.txt` — порядок станций и времена прибытия/отправления;
- `calendar*.txt` — дни действия;
- `transfers.txt` — пересадки, если заполнены;
- `shapes.txt` — геометрия линий, если заполнена.

## 3.2. Загрузка с резервированием

```python
from __future__ import annotations

from pathlib import Path
import hashlib
import time

import requests

GTFS_URL = (
    "http://transport.orgp.spb.ru/Portal/transport/"
    "internalapi/gtfs/feed.zip"
)


def download_gtfs(output: Path, attempts: int = 4) -> str:
    last_error: Exception | None = None

    for attempt in range(attempts):
        try:
            response = requests.get(
                GTFS_URL,
                headers={"User-Agent": "MetroMCP/1.0"},
                timeout=(15, 120),
            )
            response.raise_for_status()

            content_type = response.headers.get("content-type", "")
            if len(response.content) < 1_000:
                raise ValueError("Ответ слишком мал для GTFS ZIP")
            if response.content[:2] != b"PK":
                raise ValueError(
                    f"Получен не ZIP: content-type={content_type}"
                )

            output.write_bytes(response.content)
            return hashlib.sha256(response.content).hexdigest()
        except Exception as exc:
            last_error = exc
            time.sleep(2 ** attempt)

    raise RuntimeError("Не удалось скачать GTFS") from last_error
```

Обязательно храните последнюю успешно проверенную копию. Нельзя удалять рабочую версию, если свежая загрузка не прошла валидацию.

## 3.3. Проверка содержимого

```python
from pathlib import Path
from zipfile import ZipFile

REQUIRED = {
    "agency.txt",
    "routes.txt",
    "stops.txt",
    "trips.txt",
    "stop_times.txt",
}


def validate_zip(path: Path) -> set[str]:
    with ZipFile(path) as archive:
        names = set(archive.namelist())
        missing = REQUIRED - names
        if missing:
            raise ValueError(f"Нет обязательных файлов: {sorted(missing)}")
        return names
```

После скачивания желательно прогонять официальный или совместимый GTFS Validator.

## 3.4. Расчёт времени перегонов из `stop_times.txt`

```python
from zipfile import ZipFile
import pandas as pd


def gtfs_time_to_seconds(value: str) -> int:
    hours, minutes, seconds = map(int, value.split(":"))
    return hours * 3600 + minutes * 60 + seconds


with ZipFile("spb_metro_gtfs.zip") as archive:
    stop_times = pd.read_csv(
        archive.open("stop_times.txt"),
        dtype={"trip_id": "string", "stop_id": "string"},
    )

stop_times["arrival_sec"] = stop_times["arrival_time"].map(
    gtfs_time_to_seconds
)
stop_times["departure_sec"] = stop_times["departure_time"].map(
    gtfs_time_to_seconds
)
stop_times = stop_times.sort_values(["trip_id", "stop_sequence"])
stop_times["next_stop_id"] = stop_times.groupby("trip_id")[
    "stop_id"
].shift(-1)
stop_times["next_arrival_sec"] = stop_times.groupby("trip_id")[
    "arrival_sec"
].shift(-1)
stop_times["segment_seconds"] = (
    stop_times["next_arrival_sec"] - stop_times["departure_sec"]
)

segments = (
    stop_times.dropna(subset=["next_stop_id", "segment_seconds"])
    .groupby(["stop_id", "next_stop_id"], as_index=False)
    .agg(
        median_seconds=("segment_seconds", "median"),
        min_seconds=("segment_seconds", "min"),
        max_seconds=("segment_seconds", "max"),
        samples=("segment_seconds", "size"),
    )
)
```

Нужно проверить, являются ли времена реальным расписанием метро или приближённой служебной моделью. Для каждого перегона лучше использовать медиану и сохранять число наблюдений.

# 4. OpenStreetMap и Overpass API

Основные ресурсы:

- карта: https://www.openstreetmap.org/
- Overpass Turbo: https://overpass-turbo.eu/
- описание моделирования метро: https://wiki.openstreetmap.org/wiki/WikiProject_Metro_systems

OSM подходит для:

- координат станций;
- входов и выходов;
- геометрии линий;
- порядка станций в отношениях `route=subway`;
- объектов `station=subway`;
- пересадочных комплексов;
- связей с железнодорожными станциями и наземным транспортом;
- резервного обнаружения новых объектов.

Не следует считать OSM надёжным источником точного времени движения и переходов: эти данные заполняются непоследовательно.

## 4.1. Пример Overpass-запроса

```overpass
[out:json][timeout:120];
area["name"="Санкт-Петербург"]["boundary"="administrative"]->.spb;
(
  relation(area.spb)["route"="subway"];
  node(area.spb)["station"="subway"];
  node(area.spb)["railway"="station"]["subway"="yes"];
  node(area.spb)["railway"="subway_entrance"];
);
out body;
>;
out skel qt;
```

Для линий полезно фильтровать также по `network`, `operator`, `ref` и `colour`, но значения тегов нужно предварительно посмотреть в актуальных объектах, а не жёстко предполагать.

## 4.2. Ограничения

- данные редактируются сообществом;
- могут существовать дубли платформы и станции;
- отношения маршрутов могут временно быть неполными;
- названия могут различаться по языкам;
- использование публичных Overpass-серверов требует умеренной частоты запросов.

Лучше еженедельно скачивать небольшой срез Петербурга и сохранять исходный JSON.

# 5. Яндекс Метро

Официальный пользовательский сервис:

- https://yandex.ru/metro/saint-petersburg

Сервис предоставляет:

- интерактивную схему;
- расчёт времени поездки;
- маршруты с пересадками;
- информацию о закрытых станциях и вестибюлях;
- подсказки по вагонам и выходам.

## 5.1. Использование для проекта

Подходит для:

- контрольной выборки маршрутов;
- калибровки времени перегонов;
- оценки времени пересадок;
- обнаружения изменений схемы;
- проверки, какой маршрут считается оптимальным.

Веб-клиент может использовать внутренние JSON-методы, включая пакетные запросы и загрузку метаданных схем. Эти методы не являются публичным документированным API. Их структура и доступность могут измениться.

## 5.2. Как исследовать корректно

1. Открыть страницу в браузере.
2. В DevTools выбрать вкладку Network.
3. Отфильтровать `fetch/XHR`.
4. Перезагрузить схему Санкт-Петербурга.
5. Построить несколько маршрутов.
6. Найти ответы с метаданными схемы, станциями, переходами и временем.
7. Сохранить образцы ответов и определить стабильные поля.
8. Проверить условия использования сервиса до систематического сохранения данных.

Не рекомендуется делать десятки тысяч запросов для полной матрицы. Лучше восстановить веса нескольких сотен рёбер, а матрицу считать локально.

# 13. Расчёт ожидания поезда

Официальные таблицы интервалов часто задают диапазон:

```text
2:00–6:00
```

Хранить следует оба значения:

```json
{
  "headway_min_seconds": 120,
  "headway_max_seconds": 360
}
```

Для маршрута можно возвращать несколько оценок:

```json
{
  "wait_best_seconds": 0,
  "wait_expected_seconds": 120,
  "wait_possible_max_seconds": 360,
  "method": "headway_model",
  "confidence": "estimated_from_official_range"
}
```

Среднее ожидание `интервал / 2` корректно только при случайном приходе пассажира и равномерном движении. Если имеется точное расписание GTFS, лучше рассчитывать ожидание от времени запроса до следующего отправления.

Ожидание не стоит навсегда включать в статическую матрицу времени. Оно зависит от:

- времени суток;
- дня недели;
- направления;
- участка линии;
- временного графика;
- даты действия расписания.

Статическая матрица должна хранить чистое время движения и переходов. Ожидание добавляется динамически.

---

# 14. Построение матрицы времени

```python
from __future__ import annotations

import networkx as nx
import pandas as pd


def build_matrix(graph: nx.DiGraph) -> pd.DataFrame:
    stations = sorted(graph.nodes)
    lengths = dict(
        nx.all_pairs_dijkstra_path_length(graph, weight="weight")
    )

    matrix = pd.DataFrame(
        float("nan"),
        index=stations,
        columns=stations,
        dtype="float64",
    )

    for source, targets in lengths.items():
        for target, seconds in targets.items():
            matrix.loc[source, target] = seconds

    return matrix
```

Лучше использовать ориентированный граф, поскольку:

- время в противоположных направлениях может отличаться;
- первые и последние поезда различаются;
- некоторые служебные и зонные маршруты направлены несимметрично;
- временные ограничения могут действовать только в одну сторону.

Отдельно сохраняйте маршруты:

```python
paths = dict(nx.all_pairs_dijkstra_path(graph, weight="weight"))
```

# 16. План периодического обновления

## Ежедневно

- проверить официальные новости и ограничения;
- проверить страницу ремонтов;
- проверить ссылку на актуальные интервалы;
- проверить режим работы станций;
- сравнить хеши страниц.

## Еженедельно

- попробовать скачать GTFS;
- скачать OSM/Overpass-срез;
- проверить список станций и линий;
- выполнить контрольные маршруты.

## При изменении исходных данных

1. сохранить новый raw snapshot;
2. запустить парсер;
3. проверить схему данных;
4. сопоставить станции со стабильными внутренними ID;
5. сравнить число станций, линий, рёбер и пересадок;
6. проверить связность графа;
7. пересчитать матрицу;
8. сравнить 50–100 эталонных маршрутов;
9. опубликовать новую версию только после успешной проверки.

# 17. Автоматические проверки качества

Минимальный набор:

```text
Все активные станции входят хотя бы в одно ride-ребро.
Все линии имеют ожидаемые конечные станции.
Нет отрицательных и нулевых времён перегонов.
Время перехода больше нуля.
Нет неожиданных изолированных компонент.
Для каждой пары соседних станций есть источник веса.
Дата действия интервалов не просрочена без предупреждения.
GTFS ZIP проходит проверку структуры.
Новые станции не объединены со старыми только по похожему имени.
Маршруты официального интерфейса и локального графа совпадают на контрольной выборке.
```

Дополнительные предупреждения:

- число станций изменилось более чем на 2;
- исчезла линия;
- количество пересадочных рёбер уменьшилось;
- медианное время перегона изменилось более чем на 20%;
- официальный сайт обновился, но парсер не извлёк таблицы;
- GTFS старше заданного порога.

# 20. Главные риски

1. **GTFS нестабилен.** Нужен локальный архив последней успешной версии.
2. **Официальный сайт меняет датированные страницы.** Искать текущие ссылки через индексные страницы.
3. **Яндекс Метро не предоставляет публичный документированный API.** Не делать его единственной зависимостью.
4. **OSM не гарантирует время движения.** Использовать для геометрии и топологии.
5. **Пересадочные станции нельзя сливать в одну вершину.** Иначе потеряется время перехода.
6. **Интервалы — это диапазоны, а не точные отправления.** Хранить источник и уровень уверенности.
7. **Данные имеют дату действия.** Любая таблица должна быть версионирована.
8. **Пользовательские маршрутизаторы имеют лицензионные ограничения.** Проверить условия до массового сбора и хранения.
