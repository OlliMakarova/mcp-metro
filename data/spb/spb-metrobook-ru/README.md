# spb.metrobook.ru как источник графа метро Санкт-Петербурга

Ответ на вопрос: **да, с сайта https://spb.metrobook.ru/ можно получить весь взвешенный граф метро
Санкт-Петербурга для автономного расчёта быстрейших маршрутов и времени в пути** — устройство сайта
идентично московскому metrobook.ru (см. `../../mos/metrobook-ru/README.md`): граф зашит прямо в HTML
главной страницы, достаточно **одного запроса** `GET https://spb.metrobook.ru/`.

Проверка подтвердила пригодность данных: автономный расчёт маршрута «Девяткино → Купчино» по скачанному
графу даёт 52 минуты с одной пересадкой — ровно столько же возвращает собственный серверный расчёт сайта
(`totalTime: 3120` секунд = 52 минуты, `changeNumber: 1`). Посекундное совпадение подтверждает, что граф
извлечён и интерпретирован правильно.

## Как сайт устроен изнутри

Та же платформа, что и у московского metrobook.ru: маршрут по нажатию кнопки считается **на сервере**
(POST `/kcmsajax.php`), но полный граф всё равно публикуется на клиенте — он нужен странице для отрисовки
схемы.

### Структуры данных в инлайн-скрипте главной страницы

| Структура | Смысл | Пример из выгрузки |
|---|---|---|
| `mb.arrSD[sdid]` | «Станция на линии» — вершина графа: `{sid, lid, sN}` | `mb.arrSD[12]={sid: 9, lid: 1, sN: 1}` |
| `mb.arrS[sid]` | Физическая станция — группа вершин: `{sdids: [...]}` | узел «Сенная площадь»: 3 вершины |
| `mb.arrR[rid]` | Перегон: `{ttime, sdid1, sdid2, lid}`, `ttime` — секунды | `{ttime: 180, sdid1: 12, sdid2: 13}` |
| `mb.arrTT[a][b]` | Время пересадки в секундах; `999999` — переход запрещён | `mb.arrTT[6][7]=60` |
| `mb.arrL[lid]` | Линия: `{type}` — в СПб у всех линий `type: 0` (метро) | `mb.arrL[1]={type: 0}` |

Названия станций лежат в вёрстке подписей схемы:
`<span mb_sd_id='12' class='stName mbT_1'>Девяткино</span>`.

В текущей выгрузке (26.07.2026): **5 линий, 65 физических станций, 73 вершины «станция × линия»,
68 перегонов, 18 записей о пересадках**. Граф полностью связный. Времена перегонов 120–360 секунд
(кратны минуте), все пересадки — ровно 60 секунд.

### Отличия от московской страницы (важно для парсера)

1. **Контейнеры `mb.arr*` — разреженные массивы, а не объекты**: индекс 0 пуст, поэтому при обходе
   `Object.entries` пустые элементы нужно отфильтровывать (в Москве это объекты с ключами-числами).
2. **Номера линий `lid` совпадают с публичными номерами линий** метрополитена (1–5), что удобно для
   отображения; у Москвы `lid` — внутренние идентификаторы.
3. **Подписана каждая вершина «станция × линия»**, а не одна подпись на пересадочный узел, как в Москве:
   узел «Садовая — Сенная площадь — Спасская» имеет три вершины с тремя разными названиями. Поэтому
   московское ограничение «вторые названия узлов не находятся поиском» здесь отсутствует.
4. **Идентификатор схемы `mid=1`** (у Москвы `mid=2`) — нужен для запросов к серверному API.

### Серверный API расчёта маршрута (для сверки)

```
POST https://spb.metrobook.ru/kcmsajax.php
Content-Type: application/x-www-form-urlencoded

mod=metrobook&oper=getShortestPath&sdid1=12&sdid2=49&mid=1&whatToMinimize=0
```

Ответ (реальный, 26.07.2026, «Девяткино» sdid 12 → «Купчино» sdid 49):

```json
{ "success": true,
  "table": { "totalTime": 3120, "transitTime": 3060, "changeTime": 60, "changeNumber": 1,
             "ans": [12, 13, 14, ..., 49] } }
```

`totalTime` — общее время в секундах, `transitTime` — езда, `changeTime` — пересадки, `ans` — цепочка
вершин пути. Авторизация не требуется. Для автономной работы API не нужен — только как эталон сверки.

## Алгоритм автономного расчёта

Тот же, что и для Москвы (подробное объяснение алгоритмов — в `../../mos/mosmetro-ru/README.md`):
вершины — `sdid`, рёбра — перегоны и пересадки (значения `999999` отбрасываются), быстрейший маршрут —
алгоритм Дейкстры от всех вершин станции отправления до любой вершины станции назначения, варианты —
алгоритм Йена при необходимости.

## Файлы в этой папке

| Файл | Назначение |
|---|---|
| `fetch-data.js` | Скачивает главную страницу, извлекает граф и названия, сохраняет `spb-metrobook-graph.json` |
| `route-cli.js` | Автономный поиск маршрута: `node route-cli.js "Девяткино" "Купчино"` |
| `spb-metrobook-graph.json` | Нормализованный граф: станции, вершины, перегоны, пересадки |
| `index.html` | Скачанная главная страница (исходник данных, для контроля изменений) |

Запуск: `node fetch-data.js`, затем `node route-cli.js "Откуда" "Куда"`. Node.js 18+, без зависимостей.

## Наблюдения и риски

- **Нет линии 6 (Красносельско-Калининской).** Станции «Юго-Западная» и «Путиловская», открытые и
  работающие (есть на официальном сайте и в справочнике hh.ru), на схеме metrobook отсутствуют — карта
  отстаёт от развития сети. В боевом коде (`src/lib/metro-data/normalize-spb.ts`) линия 6 достраивается
  из данных двух других источников; дополнение отключится само, когда metrobook догонит.
- **Все пересадки — ровно 60 секунд.** Это модельное допущение сайта: реальные переходы в петербургском
  метро занимают 2–4 минуты. Итоговое время маршрутов с пересадками занижено относительно реальности,
  но согласовано внутри источника (серверный расчёт сайта использует те же 60 секунд).
- **Точность перегонов — минута.** Все `ttime` кратны 60 секундам.
- **Нет сведений о закрытиях.** Закрытые на реконструкцию «Фрунзенская» и «Парк Победы» присутствуют в
  графе как обычные станции — данные о временных закрытиях нужно брать с официального сайта
  (`../metro-spb-ru/`).
- **Нет координат, времени входа/выхода, расписаний.** Только граф; остальное — из справочника hh.ru
  (`../hh-ru/`) и официального сайта (`../metro-spb-ru/`).
- **Данные внутри HTML, а не в API.** Любое изменение вёрстки сломает парсер; в `fetch-data.js` стоит
  проверка правдоподобия с понятной ошибкой.
- **Сайт любительский** — авторский проект без гарантий доступности и актуальности (что уже проявилось
  отставанием по линии 6).
